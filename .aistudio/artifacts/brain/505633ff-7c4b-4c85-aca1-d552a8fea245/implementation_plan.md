# 資産管理 点検システム・変更履歴 改修計画

資産管理における「自動記録される変更監査ログ」と「人が計画・実施確認する点検管理」を分離・再構築し、資産ごとの点検項目設定、「項目設定」で選べる表のままのインライン編集、横断的な点検一覧表、予定日経過時の実施確認→確定履歴化、運転記録簿からの走行距離自動連動、および使用者カレンダーへの自動プロットを単一データソース（SSOT）設計で統合します。

---

## User Review & Critical Decisions

> [!IMPORTANT]
> 確定した4つの設計方針に加え、今回のフィードバック（項目設定での編集対象選択・最終点検日の空白表示・予定日経過時の実施確認フロー）をすべて反映しています。

- **確定方針 1（点検項目の設定単位）**: 資産1件ごとに個別の点検項目（チェックリスト）を設定・保持します。
- **確定方針 2（使用者カレンダーへのプロット方式）**: 通常の予定テーブルを複製・汚染せず、資産の点検予定データと使用者情報をメインカレンダーへ動的に自動連動表示します。
- **確定方針 3（表の直接編集対象の制御）**: 固定でハードコードするのではなく、**資産種類ごとの「項目設定」画面から、どの項目を表のままインライン編集可能にするかをチェックで選択・保存できる**ようにします（あわせて基本列の「備考」等も設定で制御可能にします）。
- **確定方針 4（点検予定の確認と最終点検日の連動・空白ルール）**:
  - 未来の点検予定は「未確定の点検予定履歴（`scheduled`）」として登録します。
  - **予定日当日以降（予定日を過ぎた点検）**について「実施したか」を確認する導線・アラート（確認待ち一覧／確認モーダル）を提示し、実施を確認したものを **確定履歴（`completed`）** として保存します。
  - 確定により未確定予定がクリアされ、確定履歴のうち最新の日付を「最終点検日」欄へ自動表示します（最終点検日フィールド自体へは保存しないSSOT方式）。
  - **確定履歴が1件もない資産の「最終点検日」は、代替文字（`-` 等）や未確定値を出さず「空白」表示**とします。

## 1. Overview & Core Concept

- **提供機能**:
  1. **予定点検の登録 → 予定日経過時の実施確認 → 確定履歴化**: 未来の点検を予定履歴として登録し、予定日を迎えた／過ぎた点検に対して「実施確認」を促します。実施確認を完了すると確定履歴として保存され、予定表示が自動で消えて確定履歴の最新日が「最終点検日」に表示されます。確定履歴がない資産の「最終点検日」は空白になります。
  2. **資産別の個別点検項目設定**: 資産ごとに専用の点検チェックリストを作成・編集でき、実施確認時に各チェック項目の状態（良好／要注意／要対応／対象外）と所見を残せます。
  3. **項目設定と連動した表のインライン編集**: 資産種類ごとの「項目設定」で「表のまま編集可」をONにした項目（例：点検予定・点検内容・点検業者・走行距離・備考など）を、モーダルを開かずに表のセル上から直接入力・保存できます。
  4. **変更監査ログと点検管理の分離**: 資産詳細内の履歴を、自動記録の「変更履歴（監査ログ）」と「点検予定・確定履歴」に分けて見やすく整理します。
  5. **運転記録簿の最新走行距離の自動表示**: 運転記録簿に記録された最新の帰着メーターを車両資産の「走行距離」欄に自動連携表示します。
  6. **横断「点検一覧」ビュー**: 全資産の点検予定、予定経過による要確認状態、確定済み最終点検日、点検項目数、実施確認操作を1つの表で俯瞰できます。
  7. **使用者メインカレンダーへの自動プロット**: 点検予定日（JST基準）を、紐づく使用者のメインカレンダー（個人／チームビュー）へ自動表示します。
- **想定利用者**: 車両や機器の使用担当者、拠点管理者、資産台帳の点検管理者。
- **主な価値**: 「予定日だけ入れて実施確認が漏れる」「項目設定と表の入力項目が一致しない」「走行距離や最終点検日の手入力・二重管理が発生する」といった現場の運用負担と記録漏れを解消します。

## 2. User Experience & Visual Design

### 主要ユーザーフロー

1. **「項目設定」で直接編集したい項目を選ぶ**
   - 資産種類の「項目設定」画面において、各パラメータ行に **「表で直接編集」チェックボックス** を追加します（あわせて「備考」などの共通欄を直接編集許可する設定も用意）。
   - 初期状態では「点検予定」「点検内容」「点検」「走行距離」「備考」などを推奨ONとし、運用に合わせて管理者が自由に追加・解除できます。
2. **表のまま直接編集（インライン入力）**
   - 資産台帳・点検一覧のテーブルでは、「項目設定」で直接編集が許可されたセルをクリックするだけで、セル内に直接入力コントロール（日付ピッカー・プルダウン・数値・テキスト）が開き、Enterまたはフォーカス外れで即時保存されます。
   - 直接編集対象外のセルや行左端の「開く」ボタンから、資産詳細モーダルを開けます。
3. **点検予定の登録と使用者カレンダーへの自動表示**
   - 表の「点検予定」セル、点検一覧、または資産詳細から予定日（JST）・内容・業者を入力すると、未確定の点検予定履歴として保存され、設定された使用者のメインカレンダー（個人・チーム）および資産カレンダーに自動プロットされます。
4. **予定日を過ぎた点検の実施確認 → 確定履歴化 → 最終点検日表示**
   - 予定日が今日（JST）以前になった未確定の点検予定は、資産台帳・点検一覧・資産詳細の上部バナーや行アクションで **「実施確認待ち」** として強調表示されます。
   - ユーザーが **「実施を確認する」** をクリックすると、資産ごとに設定した個別点検項目チェックリスト・実実施日（JST）・業者・費用・走行距離・メモを確認する画面が開きます。
   - 「実施して確定履歴に保存」を実行すると確定履歴（`completed`）として保存され、カレンダーと表の予定表示がクリアされ、**「最終点検日」に確定日が表示**されます（もし未実施で延期する場合は「予定日を変更」または「予定を取り消す」も選択可能）。確定履歴が0件の場合、「最終点検日」セルは完全に空白のまま表示されます。

### ビジュアル設計・レイアウト方針

- **高密度データグリッドと静かな空白ルール**:
  - 既存UIと調和したクリーンなライトサーフェス（白背景＋スレート系ヘアライン罫線）と単一階層設計（カードの多重ネストなし）を採用します。
  - 数値（走行距離・残日数・経過日数）と日付は `tabular-nums` で縦位置を揃えます。
  - **「最終点検日」が未確定（空白）の行は `-` や「未設定」等を無理に埋めず、意図的にすっきりした空白セル**として描画し、確定済み日付が入っている行との対比が一目で分かるようにします。
- **インライン編集と確認待ち状態の視認性**:
  - 「項目設定」でインライン編集ONにされた列のみ、ホバー時に薄い入力枠アフォーダンスを表示し、誤編集を防ぎつつ編集可能箇所を直感的に伝えます。
  - 予定日当日・超過の「要確認」行には、色だけでなく明示的なテキスト付きアクション（「実施確認」）を配置し、色覚多様性にも配慮します（アンバー＝本日/まもなく確認、クリムゾン＝予定日超過で要確認、エメラルド＝実施確定済）。
- **ゼロ・ピル・メタデータ規律**:
  - 点検項目数や出典表示（例：`運転記録簿 11/17時点`）などの補足情報は、カプセル型バッジを乱立させず、落ち着いたテキストと区切り点（`·`）で整然と表示します。

## 3. Key Product Decisions & Trade-Offs

- **決定 1: 「項目設定」主導のインライン編集フラグ設計**
  - *採用方式*: 資産種類のフィールド定義に「表で直接編集可（`inlineEditable`）」フラグを持たせ、共通列（備考など）の直接編集設定とあわせてカテゴリ単位で保存・同期します。
  - *理由*: 「この資産種類では型番も表から直したい」「管理番号は誤編集防止でモーダルのみにしたい」といった現場ごとの運用要件にプログラム改修なしで対応できます。
  - *代替案との比較*: フロントエンド側で特定キー名だけ固定で編集可能にする案は、カスタム追加項目に対応できないため不採用としました。

- **決定 2: 予定日経過の判定と「実施確認 → 確定履歴化」の厳密な区別**
  - *採用方式*: 点検ログを `scheduled`（未確認の予定）と `completed`（実施確認済みの確定履歴）と `cancelled`（未実施取消）に明確に分けます。`scheduled` のうち `eventDate <= 今日(JST)` のものを「実施確認待ち」として抽出し、ユーザーが確認・確定操作を行ったものだけを `completed` の確定履歴として永続化します。
  - *理由*: 予定日を過ぎただけで自動的に「点検済」にしてしまうと実際の未実施を見逃すため、必ず人の実施確認を経て確定履歴にする運用が安全です。

- **決定 3: 「最終点検日」の自動導出と空白表示（SSOT原則）**
  - *採用方式*: 「最終点検日」はDBへ独立フィールドとして保存せず、対象資産の `completed` 点検履歴から最新日付を動的に導出して表示します。`completed` な点検履歴が存在しない資産は、空白（`""`）として表示します。
  - *理由*: 最終点検日の手動入力や二重保存をなくし、確定履歴だけが唯一の正解（Single Source of Truth）になるため、データ不整合が起きません。

- **決定 4: 運転記録簿との最新走行距離連動とメインカレンダー動的プロット**
  - *採用方式*: 運転記録簿（月度・車両別）の最新帰着メーター値を資産取得／一覧表示時に結合・同期表示し、メインカレンダーには未確定の `scheduled` 点検予定（および確定済み履歴とは別扱いの予定表示）を使用者ID紐付けで動的オーバーレイ表示します。
  - *理由*: カレンダー側へ複製データを持たずに済むため、予定変更・実施確認・担当者変更が即座に反映されます。

### データモデルと状態の設計

- **資産種類定義（項目設定の拡張）**:
  - 各フィールド定義に `inlineEditable?: boolean`（「表で直接編集」トグル）を追加し、さらに種類単位で共通欄（例：`allowInlineNotes?: boolean`）の直接編集可否も保持できるようにします。
- **資産本体（AssetItem 拡張）**:
  - `inspectionItems`: 資産1件ごとの個別点検チェック項目配列（`id`, `label`, `method`, `sortOrder`）。
  - 導出値（DBに冗長保存せず計算で提供）：
    - `derivedScheduledInspection`: アクティブな `scheduled` 点検ログ（直近1件の予定日・種別・業者・要確認判定）。
    - `derivedLastInspectionDate`: `completed` 確定履歴のうち最新の `eventDate`（該当なしの場合は空文字 `""`＝空白表示）。
    - `derivedLatestMileage`: 運転記録簿の最新 `arrivalMeter`（日付降順最新）を基準に算出した最新走行距離と基準日・出典。
- **資産ログ（AssetLogItem 拡張）**:
  - **変更監査ログ**（`register`, `update`, `assignee_change`, `retire`）: 資産の属性・使用者・状態変更時にシステムが自動生成。
  - **点検履歴ログ**（`actionType: 'inspection'`）: `detail` に以下を保持。
    - `inspectionStatus`: `'scheduled'`（未確定予定） / `'completed'`（実施確認済み確定履歴） / `'cancelled'`（未実施で予定取消）
    - `inspectionType`: 点検種別（P点検、6ヶ月点検、車検等）
    - `vendor`: 点検業者
    - `checklistResults`: 確定時に記録した資産別点検項目のチェック結果一覧
    - `confirmedAt` / `confirmedById` / `confirmedByName`: 実施確認を行った時刻(JST)と確認者

### インタラクティブ操作と状態遷移マッピング

1. **項目設定での直接編集トグル**:
   - カテゴリ設定編集モーダルで各パラメータの「表で直接編集」ON/OFFを切り替えて保存すると、テーブル描画時に該当列のセルがクリック編集対応に切り替わります。
2. **表インライン編集の保存分岐**:
   - 点検予定関連列（`点検予定日`, `点検内容`, `点検業者`）を表上で直接変更した場合 → 既存の `scheduled` ログを更新（未登録なら新規 `scheduled` ログを作成）。空に消した場合は `scheduled` ログを取り消し。
   - 通常属性列（`走行距離`, `備考`, カスタムテキスト/日付/数値/選択肢など）を表上で直接変更した場合 → 資産更新APIへ差分保存し、変更監査ログを自動記録。
3. **予定日経過時の「実施」確認 → 確定履歴化フロー**:
   - `scheduled` かつ `eventDate <= todayJst` の予定をシステムが自動検出し、「点検一覧」上部の確認待ちセクション・対象行・カレンダー・詳細モーダルで確認を促します。
   - 「実施確認」ダイアログでチェックリスト・実実施日（初期値は予定日または今日）・費用・走行距離・メモを確認して保存すると、`inspectionStatus` が `'completed'` に確定保存されます。
   - 保存完了の瞬間、予定表示がクリアされ、確定履歴一覧への追加と「最終点検日」欄への自動表示が同期されます（確定履歴が0件の他資産は空白のまま維持）。
4. **運転記録簿・メインカレンダー連携**:
   - 運転記録簿（`driving_log`）に保存された最新の帰着メーターを、対象車両（`vehicleAssetId` および登録番号照合）の走行距離セルへ自動表示・同期します。
   - メインカレンダーは、`scheduled` 点検予定を持つ資産（使用者ID一致、または共用資産の拠点フィルタ）を JST 日付に自動プロットし、クリックでその資産の実施確認・詳細画面へ直結させます。

### 同期・互換性・品質要件

- **タイムゾーン厳守**: 予定日・確定日・予定日経過判定（「今日」との比較）・運転記録簿日付・カレンダープロットはすべて JST（`Asia/Tokyo` / `UTC+9`）基準で統一。
- **二重永続化・後方互換性**: サーバー変更時は MS SQL Server とローカル JSON バックアップの双方へ保存する既存耐障害構造を維持し、推奨サーバーコード・モジュール群を完全同期します。
- **マスターコード主軸**: 拠点・部署・使用者IDを軸にフィルタリングおよびカレンダー担当者紐付けを行います。
